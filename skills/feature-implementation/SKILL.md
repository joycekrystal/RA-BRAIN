---
name: feature-implementation
description: "Use when implementing or reviewing application features against Jira acceptance criteria, technical documentation and Figma designs."
---

Read ../delivery-standards/references/shared-rules.md and ../delivery-standards/references/templates.md. Inspect the actual repository and read authoritative feature sources. Resolve materially conflicting requirements before dependent implementation while progressing independent work. Build a short plan mapping numbered acceptance criteria to affected components, contracts, data changes and verification. Preserve architectural boundaries, type safety, validation, authorization, error handling, observability, accessibility and repository conventions. Keep changes focused, avoid secrets and sensitive logging, reuse existing components and test tooling. Add meaningful unit tests for business rules, integration tests for real boundaries and end-to-end tests for critical journeys as appropriate. Cover negative paths and regressions; do not add tests that merely mirror implementation. Run relevant existing checks and tests, report exact commands and outcomes, and distinguish executed verification from proposed/manual checks. If tooling is unavailable, say what is unverified. Update feature and technical documentation, traceability and migration/rollback notes. Include a PR-ready summary with acceptance criterion coverage and known gaps. Never mark a ticket done or claim all criteria passed without evidence; do not commit, push, merge or deploy unless authorized.
